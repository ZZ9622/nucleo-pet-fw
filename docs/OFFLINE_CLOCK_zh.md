# 有电离线自动08:00刷新

## 用户行为

- 不加RTC模块或备用电池，使用现有STM32硬件定时器维持上电时间，ESP32继续承担蓝牙透传。
- 六盒版首次启用：连接手机和小屋服务，先结算旧奖励、建立累计计数基线，再由手机校时。
- 启用后挂件保持供电，即使蓝牙断开、手机App关闭或小屋服务不可用，也按已确认时区每天08:00自动进入新周期。
- 完全掉电、MCU复位或重新烧录后，软件时钟失效；活动进度、当期已得数和累计奖励计数仍保存在Flash。重新连接手机即可校时；已经启用过的挂件，这次校时不要求小屋服务在线。
- 等待校时期间，六盒版暂停累计新的有效活动，避免把活动记进错误日期。校时后继续此前的已保存进度；不把没电的时间算成活动。
- 原30秒/三盒测试配置保留原来的行为，不启用这套离线时钟。请用当前代码的30秒参数构建；不要降级刷旧预编译固件，因为旧代码不识别新存档。

## 时间来源与时区

手机使用系统时间和小屋服务最近确认的时区（初始Europe/Stockholm）。手机应保持正常自动校时，不要通过修改手机时间测试奖励刷新。手机在连接期间每小时校准一次，冷启动会立即校准。

校时计划包含下一次当地08:00，以及未来约10年的日长度例外，覆盖夏令时23/25小时周期和半小时时区变化，不把每一天都当作86400秒。计划到期后暂停并要求手机重校，不无限猜测时区政策。

软件时钟使用TIM2连续计数，CPU因Flash写入短暂停顿不会丢掉这段时间。它仍受板载振荡器误差影响，长时间不连接手机可能漂移；这是原型软件计时，不承诺RTC级精度。若以后MCU进入STOP深度低功耗，需重新处理时钟源；当前主循环只使用普通WFI，OLED熄屏不停止定时器。

## 跨多天离线不漏发、不重复

存档v6增加 `activity_total`（启用以来累计新获得盒子数）和启用标记。每次获盒以及跨日结转获盒时，累计数与本周期进度原子保存。

服务端仍校验当前周期和配置，但发放以这个单调累计数的差额为准。比如此前入库6盒，离线几天后挂件累计20盒、当前周期只显示2盒，重连应补14盒，而不是只补当前2盒。服务把累计回执和仓库变更放进同一SQLite写事务，重试只补尚未入库的差额。已打开或放生的盒子/物品不会因重复同步恢复。

首次从旧存档启用时，旧奖励先按原账本结清，累计计数从0建立基线，不会把已领盒子重发。计数回退、当前周期不一致、超出周期上限的累计数量会停止发放，保留记录供排查。原有挂件和仓库绑定、配置迁移继承额度继续有效。

## 升级

六盒版与30秒版构建/烧录命令保持 [README](../README.md#活动自动获得盒子) 中的两套配置。六盒固件、手机App和小屋服务三端都需更新。服务沿用原数据库自动加表，先备份并停止旧服务再启动，不删除手机身份或数据库，也不要整片擦除挂件。

存档v6可读取v2/v3/v4/v5。不要刷回不认识v6的旧固件，切回测试配置时也必须从当前仓库重新构建30秒固件。

## 实物验收

1. 在线连接并同步仓库，直到六盒版显示“已校时 · 有电离线自动08:00刷新”。
2. 记下已保存秒数、当前周期已得数、仓库盒子数。断开蓝牙，挂件持续供电。经过真实08:00后，新周期额度应刷新；旧进度按阶梯结转，可能直接生成盒子。
3. 跨过多个周期后重连，仓库补齐所有离线奖励；重复同步/重开App不多发。
4. 在部分进度时完全断电，上电后显示等待校时且原进度保留。保持手机蓝牙可用，即使暂时关闭小屋服务也可完成已启用挂件的重校时。
5. 断电跨多天后只恢复到当前周期，不虚构没电期间的活动。未消费活动进度仍按既定结转规则处理。
6. 原30秒/三盒配置继续做30秒发盒、断电存进度、重复同步和三盒上限回归。

自动化用可控时钟验证8点、夏令时、计时器回绕、断电恢复以及46个跨日写入中断点，不修改真实服务或手机时钟。新增实物验收仍需朋友更新板端固件后执行。
