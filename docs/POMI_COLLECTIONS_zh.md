## 实物开盒与食物

真实模式下需要连接小屋服务（下节），并使用本次 STM32 固件。ESP32 BLE 桥保持透传，无需修改桥接协议。

1. 手机 `/prepare` 在服务端持久保留一笔物品操作，物品仍在仓库中但不能再次使用。
2. 手机通过 BLE 发出 ITEM_OPEN / ITEM_FOOD1 / ITEM_FOOD2，携带真实 petID、操作 UUID、当前宠物 revision。
3. 宠物必须在挂件上且没有交接；睡眠时先在挂件唤醒。开盒要求精力 >=10，挂件持久扣 10 并记录操作，再播放约 2.4 秒推盒到门口动画。完成后持久写回执。
4. 食物只进入等待状态，不立即消耗。屏幕显示 B1 CONFIRM FOOD；B1 的一次合格按键只确认食物，不同时执行普通喂食/重置。等待中睡着时先长按 B1 唤醒，下一次按键确认。Lv1 沿用喂食 +30 精力；Lv2 +50，上限100。
5. App 读取匹配操作 ID、petID、类型和等级的完成回执，再 `/settle` 将物品揭晓/移除。断连后从同一服务端待办恢复；不会靠点击重置回执。
6. 待确认期间禁止宠物往返。旧固件没有物品回执，不能完成该流程，需要升级。

STM32 journal 升级为 v3，仍可读取原 v2 记录；升级不清空宠物。不要刷回只识别 v2 的旧固件。存储依然使用 Flash sectors 6/7。

## 放生海服务

服务在 `server/pomi_server.py`，Python3.10+，仅标准库，SQLite 持久保存匿名身份、仓库、房间、漂流瓶和幂等请求。无需第三方 Python 包。

Mac 本地调试（在仓库根目录）：

```sh
python3 server/pomi_server.py --db /tmp/pomi-development.sqlite --host 0.0.0.0 --port 8787 --seed 20 --development
```

`--seed 20` 每次启动都会新增20个官方瓶子，普通重启不要重复传这个参数。默认海域为空，不会伪造其他玩家物品。服务端和 App 预览不共用数据。

iPhone 模拟器服务地址填 `http://localhost:8787`；实体 iPhone 使用同一网络的 `http://你的Mac名称.local:8787`。在家装小屋底部“小屋服务设置”填写，点“连接并同步仓库”。线上填写 HTTPS 地址。服务启动后另一台手机可以连接同一服务，各自自动生成匿名身份，从而互相捞到放生物品。

匿名凭据按服务地址存入本机 Keychain，不显示投放者。尚无跨手机账号找回流程，请勿删除身份或数据库。请求超时后待确认操作保存在 Keychain outbox；再次同步时以原请求ID恢复，避免因重试重复放生/捞取。

放生后物品立即从自己的仓库移出；不能撤回。捞取排除自己的瓶子；SQLite 写事务确保一个瓶子只能被一个人领取。没有瓶子时不扣机会。每3小时恢复1次，最多3次；初始3次。后台由服务端时钟决定，不能修改手机时间刷次数。捞取不扣宠物精力。

## 活动奖励与发布边界

加速度模块尚未购入，当前不能把“走出门”当作已经检测到。真实活动奖励仍待接入传感器和可信计数。暂定每累计10分钟有效活动一个盒子、每日最多3个；阈值需实测。

开发服务仅在 `--development` 时开放 `/activity`（eventID去重、每日上限）。正式服务默认关闭这个接口；App 不会把预览散步发到真实服务，避免客户端无限发盒子。

本服务可用于开发者之间的联网联调，尚未部署到公网。公开发布前还需要：HTTPS反向代理、身份找回、限流与运营备份、挂件与账号绑定、可信活动凭证和签名物品回执。目前服务信任 App 上传的 CRC 校验挂件回执，CRC用于传输检错，不是防作弊签名。不要将这一原型描述为量产级经济系统。

本轮板子不在本机：已进行 C 存储/状态机测试、Swift 逻辑测试、服务端并发测试和模拟器验证；新增 OLED 动画、按键确认和断连流程需要取回板子刷机实测。此前 BLE 往返实测结论不等于这些新增功能已实测。
