# Pomi 活动盒子 · 开发与实物测试

## 规则

正式固件累计 **600 秒有效活动获得一个盒子，每个活动归属日最多 3 个**。测试固件改为 30 秒一个，仍最多3个。活动由 LIS3DH 现有分类器判断（包括短暂保持时间），不是精确步数或GPS出门识别。只有宠物在挂件上且没有交接/存储故障时累计，睡眠不阻止携带活动。

奖励进度与当天已获得数写入同一个 Flash journal v4，每新增一整秒写一条256字节记录。App 只显示已保存的整秒进度；断电可能舍弃尚未满一秒的采样，但不会回退已显示的进度。到达阈值时进度归零与奖励计数增加原子提交，达到3个停止累计。旧v2/v3存档自动读入，不清空宠物；不要降级到无法读取v4的旧固件。

服务端使用 Europe/Stockholm 日期（可用 `--timezone` 配置），而不是手机日期。挂件没有断电走时时钟，首次需要连接小屋服务确定日期才能开始奖励累计。之后离线可继续累计，重连后补发。离线跨日不会自行重置额度：先同步旧日奖励，再确认服务端新日期；没有网络时保守保留最后确认日和上限。未满阈值的整秒进度跨日保留，达到每日上限后的额外活动不留到次日。

每天上限是活动归属日：昨天离线获得3个、今天获得3个，重连可入库两天的累计6个，但每个归属日都不超过3个。当前仍是开发者联调服务，信任App转发的CRC校验回执；量产防作弊需要设备签名。

## 数据流与重复同步

- STATUS 增加可选 `activity`：day、progressSeconds、earnedToday、intervalSeconds，旧固件仍兼容（App提示需升级）。
- App 蓝牙轮询取得完整回执，在小屋服务已连接时自动 POST `/activity/sync`。
- 服务在SQLite同一写事务中，以 `(petID, day)` 核对累计已领取数、发放差额、更新仓库。每个挂件绑定一个仓库，每个仓库一个活动挂件，避免换匿名身份重复领取。
- 服务回传当前日期与旧日已确认数。App通过 `ACTIVITY_SYNC` 同步日期，挂件只有旧日奖励已被确认后才进入新日，避免跨日清空未发奖励。
- App按新奖励或每分钟检查日期同步；网络失败以钥匙串outbox保存原请求，恢复后自动重试，不重复发放。
- 服务端数据库丢失不等于可重置奖励。保留原DB和手机身份，不要删除App或擦除挂件日志。

## 构建

正式固件（默认）：

```sh
cmake -S . -B build/activity-production -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi-gcc.cmake -DPOMI_ACTIVITY_SECONDS=600
cmake --build build/activity-production
```

短周期固件：

```sh
cmake -S . -B build/activity-test -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi-gcc.cmake -DPOMI_ACTIVITY_SECONDS=30
cmake --build build/activity-test
openocd -f openocd/nucleo-f401re.cfg -c "program build/activity-test/pet.hex verify reset exit"
```

不要执行 mass erase。HEX仅包含程序区，烧录应保留原存档扇区6/7。ESP32 BLE透传桥无需更新。

服务需与固件周期匹配。已有测试数据库可原地升级，表结构自动补充，原仓库、食物和漂流瓶保留：

```sh
python3 server/pomi_server.py --db /你的原数据库路径/pomi.sqlite --host 0.0.0.0 --port 8787 --development --activity-seconds 30
```

正式服务默认600秒。30秒服务必须显式 `--development`。从测试转正式应先用原配置将所有奖励同步入库，再同时切换固件和服务到600秒；服务保留当天计数，已领3个不会因为换配置重新发放。若原正式进度已超过30秒，不要刷短周期固件测试，避免配置冲突。正式/测试活动进度共用原挂件存档，不会通过重刷清空上限。

## iPhone 实物验收

1. 更新App，朋友烧录30秒测试固件，连接相同小屋服务。
2. 手机蓝牙连接Pomi，同步真实仓库。挂件页/小屋页显示“短周期测试 · 30秒/盒”，首次日历确认后开始累计。
3. 记下仓库盒子总数。托稳挂件活动约30秒，进度到30后归零，今日已获得变1，仓库只增加1个盒子。分类器保持/采样会影响实际等待时间。
4. 暂停在例如12秒，断电再上电，重新连接应显示已保存的12秒。继续18秒左右，累计到30后才获得下一盒。
5. 在活动满周期后、入库前关闭手机蓝牙；重新连接应补发且只发一次。重复同步仓库、断连重连、重开App不增加重复盒子。
6. 累计得到3盒后继续活动，不应出现第4个；进度停在上限。不要改手机时间测试换日。
7. 跨日和网络失败已通过自动化测试；真实跨日需服务端日期自然更新，断网时不重置日额度。

手动放入的测试盒子与活动奖励是不同来源，不计入“今日活动3个”。本轮不会清空之前开盒、食物和放生海数据。

## 自动化

`make test` 同时测试600秒和30秒固件状态机，包含40个奖励写入中断点；`python3 -m unittest discover -s server -v` 验证服务事务去重、日期、上限、绑定和配置；`swift test --package-path ios` 验证回执、CRC和兼容性。新增实物测试需要朋友完成烧录后执行，自动化通过不能代替实物结果。
