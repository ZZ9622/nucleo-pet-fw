# Nucleo Pet — STM32 电子宠物

基于 **NUCLEO-F401RE** 和 **SSD1306 OLED** 的电子宠物固件，使用裸机 C 编写。
项目从 **Demo 0.1** 起完成实物连接与烧录验证；当前代码增加了四键控制、双属性养成、闲置熄屏和更多动画，新增行为仍需按下文在实物验收。

本 README 记录当前硬件范围、已实现功能和 **macOS** 开发流程。

## 开发记录

- **2026-10-25 · Demo 0.1**：完成 STM32 NUCLEO-F401RE 与 OLED 的初步物理连接，
  完成首代电子宠物 Demo 烧录并确认实物正常运行；实现小猫动画、属性显示、
  喂食、睡眠 / 唤醒、重置及 LED 状态反馈。

## 适用范围与接线

| 项目 | 当前配置 |
| --- | --- |
| 开发板 | ST NUCLEO-F401RE（STM32F401RE） |
| 屏幕 | Joy-IT SBC-OLED01，SSD1306，128×64，四针 I²C |
| 操作输入 | 板载 B1（PC13）与四个可选外接按键，见 [接线指南](WIRING_zh.md) |
| 状态指示 | 板载绿色 LD2（PA5） |
| 烧录与调试 | 板载 ST-LINK/V2-1，通过 CN1 USB 接口连接 Mac |
| 开发环境 | macOS、CMake、Arm GNU 编译器、OpenOCD |

当前屏幕驱动按 SSD1306 编写，不适用于 SH1106（如 SBC-OLED01.3）。
其他开发板、屏幕控制器或引脚配置需要调整代码后使用。

### OLED 接线

断电后按模块上的引脚文字连接：

| OLED | NUCLEO-F401RE |
| --- | --- |
| GND | GND |
| VCC / VDD | 3V3 |
| SCL / SCK | PB8，Arduino D15 / SCL |
| SDA | PB9，Arduino D14 / SDA |

驱动固定使用 PB8/PB9，I²C1 速率为 100 kHz，自动依次尝试七位地址 `0x3C`、`0x3D`。
SCL、SDA 需要上拉到 **3.3V**；若模块没有自带上拉，可各接一只约 4.7 kΩ 电阻到 3V3。

使用 **USB-A 转 Mini-B 数据线**连接 Mac 与开发板的 **CN1 / ST-LINK USB**；
Mac 只有 USB-C 接口时，可使用支持数据传输的转接器。
保留 CN2 原厂跳帽，PA13/PA14 留给 SWD 调试，无需另接 USB 转串口模块。

## 当前功能

### 屏幕与动画

- 启动约 2.5 秒棋盘测试后进入方块猫界面。
- 顶部显示 HAPPINESS / ENERGY（0–100）及状态条，侧边显示动作反馈。
- 支持眨眼、走动、跳跃、打哈欠、睡眠和瘫软动画，规则见下文。
- 30 秒闲置熄屏，首次按键只唤醒屏幕。

### 按键操作

所有操作都在 **松开 B1 后**触发：

| 操作 | 功能 |
| --- | --- |
| 短按，不足 1.2 秒 | 喂食（清醒时有效） |
| 按住至少 1.2 秒、不足 5 秒后松开 | 睡眠 / 唤醒 |
| 按住至少 5 秒后松开 | 重置宠物属性 |

按键已做消抖，极短的触碰会被忽略。屏幕底部的 `2S SLEEP` 是操作提示，
实际睡眠切换阈值为 1.2 秒。

### 宠物状态与 LED

宠物状态每秒推进一次，使用 `PET_RULES_DEFAULT` 的日常养成规则。
喂食增加体力，抚摸和玩耍增加心情，睡眠恢复体力；连续 24 小时未喂食会进入可救助的瘫软状态。
外接 Feed / Pet / Sleep / Play 四键的接线见 [四按键接线指南](WIRING_zh.md)。

绿色 LD2 同步提供反馈：启动或重置时闪两次，喂食后快闪四次，
日常状态为双脉冲心跳，需要照顾时周期闪烁，严重状态快闪，睡眠时为慢速心跳。

### 当前边界

- B1 保留喂食、睡眠/唤醒与重置；可选外接四键增加抚摸和玩耍入口。
- 保留经验、金币、成长阶段和小游戏奖励接口，尚无可玩的小游戏。
- 已移除旧版 FOOD / JOY / CLEAN / HEALTH 五属性，改为 Happiness / Energy 双属性。
- 尚未实现存档、实时时钟、声音、传感器或联网；断电或复位会重新初始化宠物。

## macOS 开发与烧录

### 1. 安装工具

需要 Xcode Command Line Tools（提供本机 C 编译器、Git 和 Make）。
若尚未安装：

```sh
xcode-select --install
```

安装 [Homebrew](https://brew.sh/) 后，安装项目工具：

```sh
brew install cmake arm-none-eabi-gcc open-ocd
```

项目要求 CMake 3.20 或更高版本，不依赖 STM32CubeIDE 或 HAL。
工具包说明：[CMake](https://formulae.brew.sh/formula/cmake)、
[Arm 编译器](https://formulae.brew.sh/formula/arm-none-eabi-gcc)、
[OpenOCD](https://formulae.brew.sh/formula/open-ocd)。

### 2. 获取项目

```sh
git clone https://github.com/ZZ9622/nucleo-pet-fw.git
cd nucleo-pet-fw
```

已有仓库时，直接进入项目目录即可。

### 3. 测试、编译与烧录

连接 CN1 后，在项目根目录依次运行：

```sh
make test       # 在 Mac 上运行宠物规则和界面绘制测试
make build      # 编译 STM32 固件
make probe      # 检查 ST-LINK 和 STM32 连接，不写入 Flash
make flash      # 写入、校验固件并自动复位
```

确认 `make probe` 成功识别开发板后再执行 `make flash`。
编译产物位于 `build/nucleo-f401re/`，包括 `pet.elf`、`pet.bin` 和 `pet.hex`。
`make test` 和 `make build` 无需连接开发板；六项本机测试覆盖规则、界面、按键、熄屏、每日照顾和动画，
不替代实物验证。

烧录完成后，LD2 应先闪两次，OLED 显示棋盘图案后进入小猫界面；
可通过短按 B1 验证喂食，通过长按后松开验证睡眠 / 唤醒。

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 无法识别 ST-LINK | 检查是否使用数据线、是否接在 CN1、转接器是否支持数据传输，以及开发板是否通电 |
| LED 正常但屏幕不亮 | 检查 3V3、共地、SCL/SDA 接线、上拉及焊接；确认屏幕控制器为 SSD1306 |
| 移动项目后 CMake 报路径错误 | 执行 `make clean` 清除生成的 `build/` 目录，再执行 `make build` |
| 安装 OpenOCD 后仍提示未找到 | 确认终端能运行 `openocd --version`，然后执行 `make clean`、`make build` 重新配置 |

屏幕通信出错后，驱动约每秒重试初始化；单次 I²C 事务有超时限制。
若总线卡住，可断电检查接线后重新上电。
调试时可查看 `oled_status`：`0` 等待上电、`1` 无应答或总线故障、
`2` 棋盘测试、`3` 宠物画面、`4` 闲置熄屏。

## 双属性与每日喂食

Happiness 初始 75、Energy 初始 80，范围 0–100；`is_sleeping` 独立。
清醒累计每小时两值各减 1；睡眠累计每分钟 Energy 加 1，Happiness 不减。
两种时间累计独立保留，反复切换睡眠不会跳过衰减。
Feed 增加 Energy 30，Pet 增加 Happiness 10，Play 增加 Happiness 20、消耗 Energy 12。
常规睡眠中忽略 Feed/Pet/Play，须先唤醒。

从开机或最近一次有效喂食起连续 24 小时未喂食，进入瘫软状态，Energy 归零，
猫猫趴在地上轻微呼吸，侧边 FEED ME；瘫软后暂停属性增减直至救助。此判定独立于心情与精力，睡眠也不能替代喂食。
瘫软期间仅喂食或重置有效；喂食可直接救助（即使此前正在睡眠），清除瘫软并唤醒，
Energy 恢复到 30，重开滚动 24 小时窗口。不加入死亡或不可逆惩罚。
屏幕熄灭时继续计时；首次按键仍只唤醒屏幕，再次按 Feed 才喂食。
等级、经验、金币、小游戏结果接口保留，但游戏奖励不重置喂食计时。

当前按持续通电运行时间计算，未实现 RTC/断电存档；断电、复位或 B1 重置会重新开始。
真正跨断电的每日照顾需要后续增加存档与可信实时时钟。
规则配置在 `PET_RULES_DEFAULT`；期限在 `PET_FEED_DEADLINE_S`，正式固件为 86400 秒。
测试以模拟时间推进，无需实际等待一天，也不缩短正式固件期限。

### 方块猫外观

猫猫改为参考图的实心像素轮廓：方耳、阶梯形脸颊、平底下巴，眼睛与嘴巴镂空。
单色 OLED 使用亮色身体与黑色五官，无法显示参考图中的蓝色。
HAPPY 为弯眼笑脸；CONTENT 为方眼小嘴；NEEDY 为方眼下弯嘴；
HELP 为疲惫眼睛、下弯嘴与闪烁感叹号；SLEEP 为闭眼细嘴与飘动 Z。
保留眨眼及一像素起伏，四键、属性和显示驱动不变。

## 闲置熄屏与按键唤醒

30 秒没有按钮活动后，OLED 发送 SSD1306 `0xAE` 关闭显示，并暂停像素刷新。
宠物计时、Happiness/Energy、睡眠恢复及 LED 仍运行；这不是断电，也不是 MCU STOP 模式。
四个外接按钮与板载 B1 均可在按下稳定约 25ms 后唤醒。
首次按键仅唤醒，直到所有键松开前均忽略动作（包括 B1 长按重置）；再按才执行原功能。
按住按钮不会熄屏，松开后重新计时。熄屏不改变宠物的 `is_sleeping`。
唤醒时先在暗屏中写入完整最新画面，再发送 `0xAF`，正常约 0.16 秒，避免旧画面闪现。
上电棋盘测试保留，正常闲置唤醒不重播测试图；I2C 故障重连仍保留原初始化测试。
屏幕失联时沿用超时与每秒重试；重连后服从当前熄屏请求。
等待时间可修改 `include/screen_idle.h` 中的 `SCREEN_IDLE_TIMEOUT_MS`。
调试状态 `oled_status=4` 表示闲置熄屏。

板上验收：烧录后等待 30 秒确认熄屏；任意按钮按下确认亮屏且无喂食/睡眠/重置；
松开后再按确认动作；睡眠中熄屏、唤醒屏幕后仍应是睡眠。
主机测试覆盖超时边界、计时溢出、按住不熄屏与唤醒按键吞掉动作；仍需在实物确认显示命令与时序。

## 五种基础动画

保留参考方块猫造型，`pet_animation_sample` 仅采样画面，不修改属性或游戏随机数。
- Blink：每 6 秒窗口中伪随机选一个时刻闭眼约 220ms；走动时也可眨眼。
- Walk：偶尔左右走动最多 7 像素，交替抬脚后回到中心，精力 >35 才出现。
- Happy Jump：心情 >=75、精力 >=60 时更容易随机跳跃；有效 Play 后立即播放一次约 1.2 秒跳跃。
- Yawn：精力 <=35 时周期性打哈欠，精力 <=10 时优先连续打哈欠。
- Sleeping：闭眼、小幅呼吸起伏、飘动 Z；用户可主动睡眠。

精力 <=10 连续约 3 秒自动进入睡眠，睡眠键可唤醒；若精力仍低，约 3 秒后会再次入睡，
可在此期间喂食恢复。24 小时未喂食的瘫软状态优先于睡眠，只有喂食才能救助。
动画在屏幕中央范围绘制，不遮挡指标与侧边反馈。动画本身不增减属性，睡眠状态仍按规则恢复精力。
伪随机动画采用稳定的时间散列，同一开机时间序列可复现；没有依赖硬件真随机数。
电脑端动画测试覆盖边界、双向走动、Play 跳跃、打哈欠/睡眠/瘫软优先级、自动睡眠与救助。

### 侧边反馈布局

删除底部状态栏与全宽分隔线，反馈放在宠物左侧 x=2..28，多词反馈分两行显示。
宠物活动区域向下延伸 6 像素，瘫软的地面线移到 y=61；顶部两行指标保持不变。
