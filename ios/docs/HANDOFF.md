# 同一只宠物，两个居所

## 产品约定

宠物拥有稳定的 `petID`。它可以位于 `device`（实体挂件）或 `phone`（手机小屋），
任一时刻只有一端负责推进状态和接受照顾。另一端显示“去对方那里玩了”，不创建第二只宠物。
睡眠是生活状态，与居所和屏幕亮灭独立；睡着的宠物可以保持睡眠状态迁移。

当前 App 的 `device` 是本机模拟居所，不代表已经有真实 STM32 连接。
当前固件也没有稳定 petID、通信、持久化或跨设备时间协议，必须后续实现。

## 当前原型实现

`CompanionSession` 保存唯一宠物状态和所属居所：

1. `beginTransfer` 先按经过时间更新，然后产生唯一 `transferID`、下一次 revision 和完整状态快照。
2. 将待交接记录保存后进入旅途。此时停止接受照顾，原居所仍是所有者。
3. 模拟接收端确认后，`completeTransfer` 校验 transferID、petID、来源、revision 和状态一致性，
   更新居所并补算经过时间。相同已完成回执再次到达时不重复执行。
4. App 重开后加载待交接记录，用户可以继续。
5. 只有单进程模拟中可以直接撤销：原居所从未失去状态，且没有外部接收副本。

`CompanionStore` 使用“复制候选状态 → 原子保存 → 发布到 UI”的顺序提交互动与交接，
保存失败时不发布这次操作。定时状态在内存每秒补算、约每 15 秒保存，离开前台时再保存。
首次发现文件损坏不会自动覆盖；恢复操作会先备份。

## 迁移不能只复制两个属性

双属性只是显示内容。为与原 C 规则连续衔接，还必须携带：

- `energy`、`happiness`、`is_sleeping`
- `seconds_since_feed`，保留每日喂食期限
- `awake_decay_elapsed_s`、`sleep_recovery_elapsed_s`，保留未满一小时／一分钟的累计时间
- `low_energy_awake_s`，保留自动入睡进度
- `experience`、`coins`、`level`、`stage`
- `game_time_s`、`rng_state`、`feedback`
- 宠物 ID、当前所有者、状态 revision、规则版本、序列化版本和计时基准

不要直接传输 C struct 的内存字节，避免填充、字节序和 ABI 差异。
App 原型使用显式 Codable 字段，未来传输层也应使用明确版本的编码。
`PetSnapshot` 缺少时间累计和内部字段，只适合显示，不足以用作完整迁移记录。

## 实物接入时必须补齐

以下是后续要求，不是本版已实现功能：

1. 选定与 iPhone 兼容的通信路径，并在固件实现命令收发。
2. 固件支持稳定身份、完整状态导出／导入以及断电后的持久化。
3. 双端实现 durable prepare / receipt / commit：发送端冻结，接收端先可靠保存待接收状态，
   再确认最终归属。双方均以 petID、transferID、revision 去重。
4. 断连后查询事务状态再继续；一旦对端可能已确认接收，不能仅凭超时撤销并重新创建所有者。
   当前模拟器的直接撤销方法不可原样接到真实硬件。
5. 配对认证与版本兼容检查；收到未知规则版本或损坏数据时保留原状态，拒绝接管。
6. 明确持续通电时间、本机墙上时钟、RTC 与断电时间的关系，避免重复计算或漏算。
7. 板子在宠物离开后显示出门状态，并停止本地照顾；返回确认后恢复唯一活动实例。

需要在两台设备上测试：传输任一步断电、重复包、乱序包、手机后台终止、蓝牙重连、
旧版本固件，以及回执丢失。当前 14 项本机测试不能替代这些实物联调。
